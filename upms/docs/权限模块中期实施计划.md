# 权限模块中期实施记录

## 背景

权限定义表 `iam_permission` 中的 `module_code` 当前用于权限分组、排序和展示。它不是导航节点编码，也不是后端包名或业务代码模块主键。

中期目标是把 `module_code` 升级为“权限模块目录编码”：由独立目录维护模块名称、排序、启停和层级信息，权限定义继续保存 `module_code`，通过服务层校验保证一致性。

## 设计原则

- 权限模块目录是权限的分类维度，不直接等同于导航、菜单或后端代码模块。
- 导航和权限仍通过 `ui_navigation_permission.permission_id` 关联。
- 角色和权限仍通过 `iam_role_permission.permission_id` 关联。
- `iam_permission.module_code` 暂不加数据库外键，避免历史数据、扩展模块和种子数据被强耦合。
- 删除权限模块时优先软删除，并在服务层检查是否存在子模块或权限引用。

## 数据库实现

新增 Flyway 迁移 `V016__permission_module_catalog.sql`，创建权限模块目录表 `iam_permission_module`。

计划字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `BIGINT` | 主键，使用雪花 ID |
| `module_code` | `VARCHAR(64)` | 模块编码，唯一 |
| `module_name` | `VARCHAR(128)` | 模块名称 |
| `parent_code` | `VARCHAR(64)` | 父模块编码，可空，仅普通索引 |
| `sort_order` | `INT` | 排序号 |
| `status` | `VARCHAR(32)` | 状态，`ACTIVE` 或 `INACTIVE` |
| `remark` | `VARCHAR(500)` | 备注 |
| `deleted` | `TINYINT` | 逻辑删除 |
| `creator_id` | `BIGINT` | 创建人 ID |
| `created_at` | `DATETIME(3)` | 创建时间 |
| `updater_id` | `BIGINT` | 更新人 ID |
| `updated_at` | `DATETIME(3)` | 更新时间 |

初始数据包含现有权限已使用的可授权模块编码：

`dashboard`、`system`、`org`、`user`、`role`、`navigation`、`permission`、`dictionary`、`setting`、`announcement`、`file`、`audit`、`auth`。

个人中心 `profile` 调整为登录后公共能力，不再进入权限模块目录、权限定义、角色授权或导航授权；后续迁移 `V017__profile_login_only_permission_cleanup.sql` 用于补齐模块目录并清理历史 `profile:*` 授权数据。

## 后端实现

在 `core.identity.permission` 下新增权限模块目录能力：

- 新增实体、Mapper、Service、请求模型和视图模型。
- 使用 XBatis 注解与现有 `SoftDeletableEntity` 基类。
- Service 内实现分页、详情、选项列表、创建、更新、删除。
- 创建或更新权限定义时，校验 `moduleCode` 必须存在于启用且未删除的权限模块目录。
- 删除权限模块时，如果存在未删除子模块或权限引用，返回业务错误。

在 `application.upms.identity.permission.controller` 下新增管理端入口：

- `GET /admin/permission-module/page`
- `GET /admin/permission-module/options`
- `GET /admin/permission-module/{id}`
- `POST /admin/permission-module`
- `PUT /admin/permission-module/{id}`
- `DELETE /admin/permission-module/{id}`

权限控制复用现有权限定义管理权限：

- 查询与选项：`system:permission:view`
- 创建：`system:permission:create`
- 更新：`system:permission:update`
- 删除：`system:permission:delete`

## 测试覆盖

新增或补充测试场景：

- 创建权限模块时校验 `module_code` 唯一。
- 更新权限模块时禁止父级设置为自己。
- 删除存在子模块的权限模块应失败。
- 删除已被权限定义引用的权限模块应失败。
- `options` 只返回启用且未删除的模块。
- 使用不存在或停用的 `moduleCode` 创建权限定义应失败。
- 使用启用模块创建或更新权限定义应成功。
