# upms-web 测试计划

## 目标

本计划覆盖 upms-web 当前路由和核心业务能力，产物包括自动化测试与手工测试用例。覆盖策略采用“核心流程优先”：每个页面至少验证可访问、数据加载、查询/重置/分页、主要写操作入口、表单校验、权限或异常状态。

## 测试范围

- 认证与路由：登录、登出、未登录拦截、权限拦截、首次改密拦截。
- 基础框架：布局、侧边栏、面包屑、权限指令、用户权限组合式函数。
- 业务页面：仪表盘、用户、角色、权限、导航、部门、字典、系统配置、在线会话、文件、审计、公告、消息中心、个人中心。
- API 基础设施：统一请求工具、JSON 请求、FormData/XHR、下载、401 处理、业务错误提示。
- Store：用户登录态、权限过滤、角色/权限/组织缓存与刷新。

## 自动化分层

- 单元测试：`pnpm test:unit`
  - 路径：`src/**/__tests__/**/*.test.ts`
  - 重点：纯逻辑、请求封装、Store、权限判断。
  - 不依赖后端。
- E2E 测试：`pnpm test:e2e`
  - 路径：`tests/e2e/**/*.spec.ts`
  - 重点：真实后端登录、权限路由、403/找回密码等独立页面、页面渲染、查询/重置/表单校验。
  - 默认后端：`http://localhost:8004`，可用 `E2E_API_BASE_URL` 覆盖。

## 后端不稳定处理

开发安全加固期间后端可能不定期断开。E2E 在每条用例开始前会调用真实登录接口做可用性探测：

- 登录接口不可用、超时或未返回 token：当前用例跳过，并输出后端不可用提示。
- 登录探测成功后，页面流程中发生断连：用例失败，保留 trace、截图和视频，作为真实回归或环境波动诊断依据。
- 单元测试不访问后端，不受后端断开影响。

## 测试数据策略

- E2E 新增或修改数据统一使用 `e2e-` 前缀。
- 删除类用例只删除本轮创建的数据。
- 清理失败时不删除非 `e2e-` 前缀数据。
- 当前首批 E2E 以真实环境冒烟、查询、弹窗和校验为主，避免在不稳定后端上制造大量持久数据。

## 执行顺序

```bash
pnpm type-check
pnpm lint
pnpm format:check
pnpm test:unit
pnpm test:e2e
pnpm build
```

## 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `E2E_BASE_URL` | `http://localhost:5173` | 前端地址 |
| `E2E_API_BASE_URL` | `http://localhost:8004` | 后端地址 |
| `E2E_USERNAME` | `admin` | E2E 登录账号 |
| `E2E_PASSWORD` | `admin` | E2E 登录密码 |

## 通过标准

- 单元测试全部通过。
- 后端可用时，E2E 登录、路由冒烟和核心页面流程通过。
- 后端不可用时，E2E 用例显示明确跳过原因，不阻塞单元测试结果判断。
- 手工 P0/P1 用例在提测前完成验证，严重问题必须修复或记录风险。
